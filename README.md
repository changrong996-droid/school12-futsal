# 第12学校的五人制足球赛

一个像素风的三维立体模型，整个应用就是一个 HTML 文件。漂浮的小岛上有一块蓝色橡胶球场（可以切换场地材质）、一栋教学楼、坐满孩子和家长的看台，还有一个比赛引擎，会完整地踢完一场比赛：球员入场、热身、列队、上下两个半场、中场休息、全场结束、赛后握手，最后一起走回教学楼。

**在线体验：** https://changrong996-droid.github.io/school12-futsal/

使用 three.js r160，通过 import map 从 jsDelivr 加载。不需要构建：`index.html` 就是整个应用。界面为简体中文，页面上的文字使用系统自带的中文字体（苹方、冬青黑体、微软雅黑、Noto Sans CJK），不下载任何网络字体；三维场景里的文字（记分牌、校牌、小卖部招牌、旗帜）用内嵌的像素字体位图，见下文“字体”。

## 内容

- **渲染：** 正交相机以 31° 俯角、45° 方位角渲染到低分辨率画布，并带深度纹理。后处理会在深度突变处描黑边，把每个像素对齐到固定的 32 色调色板，再按整数倍放大显示（像素始终清晰）。
- **画质档位（2026-11-03）：** 档位按“一个美术像素占几个屏幕像素”定义：经典 ≈4、标准 ≈3、精细 ≈2（1280×800 桌面上分别是 320×200、427×267、640×400 的内部画面；手机按宽度，经典/标准/精细约 240/320/427）。美术按“每米多少像素”设计，以标准档为基准：场地四种表面（每米 16/24/32 纹素）、可平铺草地、教学楼砖墙、门柱条纹和阴影贴图都按档位重新生成；场地纹理用只取原色的 mip 链，远处的标线不会出现混色碎点。精细档的外轮廓描 2 像素、内部折线仍是 1 像素；天空渐变带有序抖动，不出色带。
- **场景：** 40×20 米的球场，四周是带门的铁丝网。场地有完整的五人制标线、3×2 米的条纹球门和球网、两队替补席和记录台。三面是看台。教学楼有门廊、球队进出的大门、挂钟、旗杆、“第12学校”校牌和一块 64×32 的记分牌。周围还有游乐场、自行车棚、小仓库、篮球架、小卖部、树木、球童、摄影师、保安和四座照明灯塔。每次旋转视角后，离镜头最近的那一侧围网和看台会被切掉。
- **人物：** 所有人共用一套骨骼（髋、胸、头、上臂、前臂、大腿、小腿），由一个 InstancedMesh 绘制全部身体部件，看台观众用同一套骨骼的精简版本。每个人都有独立的头、几种发型和发色、躯干、短裤、袜子和球鞋、手臂，身高和体型略有不同，孩子明显比大人矮小。球衣有撞色袖子和肩部饰条，背后印有号码（放大后可以看清），每队一名队长戴袖标，守门员穿不同颜色的长袖球衣、长裤并戴手套。裁判和记录员穿天蓝色上衣配黑色袖子，与任何球队和场地颜色都不同。动作包括跑步（摆臂、屈膝、上下起伏）、站立时的轻微晃动、踢球（支撑脚加摆腿）、守门员的预备蹲姿和鱼跃扑救、进球后举手庆祝和跪地滑行、握手、替补席和看台上的坐姿，以及观众各自错开节奏的鼓掌、跳起和挥手。摄影师拿着带闪光灯的相机（单膝跪地拍摄），保安戴帽子穿反光背心，球童穿橙色号码背心，小卖部店员系着围裙。
- **比赛引擎：** 四支原创球队（河畔水獭队、山岗彗星队、枫林狐狸队、北门猫头鹰队），每队九名球员，采用 1-2-1 阵型。比赛中会滚动换人。出界后以边线球、角球、球门球（守门员手抛或传出）和任意球恢复比赛。一支球队第 6 次及之后的每次犯规都判罚 10 米球，禁区内犯规判罚 6 米点球。皮球物理包含二次空气阻力、弹跳、滚动阻力和由滑动转为滚动的过程。传球和挑传的力度由解析求解器计算。人物由生成器协程驱动，并用 A* 在岛上寻路。
- **场景文字（2026-11-03）：** 记分牌、校牌、小卖部招牌和旗帜上的字都用开源像素字体“缝合像素字体”（Fusion Pixel Font，8/10/12 像素）的位图字形：构建时只把场景里真正用到的字符（数字、字母、队名和招牌上的汉字）转成 1 位位图嵌进 `index.html`，无抗锯齿，按整数倍放大。每块招牌每帧量一下它在屏幕上占多少像素，按 1 纹素 = 1 屏幕像素重新排版，挑放得下的最丰富版式；招牌是斜着贴在墙上的，字形会被逐列校正成在屏幕上直立、不断笔画。记分牌有三种版式：全场镜头只显示比分和时间（8 像素数字，最远处退回 3×5 小数字）；中等距离加上拼音缩写的队名代码（SHT 水獭、HXG 彗星、HLI 狐狸、MTY 猫头鹰，10 像素）；转播/特写镜头放得下时显示中文队名（12 像素）和放大的比赛时间、半场、全队犯规点。页面左上角的计分条照旧显示中文队名。
- **合批提速与像素描边（2026-11-03）：** 场景搭好后，所有静止的物体（教学楼、围网、看台、门柱、替补席、灯塔、游乐场、小仓库等）按“被哪一侧切掉 × 材质 × 阴影设置”合并成二十几个大网格：纯色方块共用一个顶点颜色材质（颜色写进顶点，光照不变），带贴图或会随时段变化的材质（砖墙、门柱条纹、窗户、灯）按材质合并；球网每张合成一个。静态阴影不再每帧重画：开局、换时段、换画质或视角切掉另一侧时才把静止物体画进阴影贴图并存一份，之后每帧只在人物和球经过的矩形里把这份静态阴影（颜色和深度）拷回去，再把人物、球和旗子画进去，阴影效果和以前一样。每帧总绘制调用（阴影 + 主画面 + 后处理）从 357 次降到 83 次（其中 31 次是新加的法线通道，关掉折线高光是 52 次）；在 Apple M4（Chrome，Metal）上同机交替测，一帧 GPU+CPU 总时间约少 10%，CPU 提交时间约少 30%。描边沿用 three.js 官方 RenderPixelatedPass 的做法：除了深度（外轮廓仍描黑，精细档 2 像素），再画一遍视角空间法线，在同一表面的折线处只让朝 (1,1,1) 一侧的那个像素变亮——取同一色系里更亮一级的调色板颜色（草绿→浅绿、石板灰→灰），不会跳色；人物、球和观众太小，不加折线高光，保持轮廓干净。镜头：相机一直按美术像素网格吸附（平移时整幅画面整像素移动，不会闪），新加的是 t3ssel8r 式亚像素平滑：吸附丢掉的那一点位移在最后放大显示时按屏幕像素补回去（画面四周多画 1 个美术像素防止露边），所以镜头移动是一屏幕像素一屏幕像素地走，而不是一次跳 2–4 个屏幕像素。

## 操作

画面铺满整个浏览器窗口，页面不滚动。比分条在画面顶部，解说以电视字幕的形式叠在画面底部（显示最新两条，点一下可以展开全部历史）。所有比赛控制都收在左下角的“战术板”里：点小黑板（或按 M 键）展开，点外面或按 Esc 收起；手机竖屏时战术板从底部弹出，横屏时从左侧滑出。窗口大小改变时，像素画面按整数倍重新计算，像素格始终清晰。

| 控件 | 作用 |
|---|---|
| ⟲ ⟳（画面上） | 以 90° 为单位旋转视角 |
| + −（画面上） | 放大、缩小 |
| 对阵 | 选择主队和客队，或点“随机对阵”（会开始一场新比赛） |
| 比赛时长 | 两个半场大约占用的现实时间：4、8、12 或 20 分钟（每个半场的比赛时间为 20 分钟） |
| 场地材质 | 橡胶、沥青、人造草或木地板。会改变球场外观和皮球物理（弹跳、滚动、滑动）。在木地板上球员会有点打滑 |
| 时段 | 白天、黄昏或夜晚。改变天空和光照；黄昏和夜晚会打开照明灯和教室的灯 |
| 镜头 | 转播跟随、全场或特写 |
| 观众互动 | “射门！”“横传”“长传”会影响持球球员的下一个动作 |
| 点击球场 | 放置一个标记，下一脚传球会传到那里 |
| 播放 | 暂停/继续、1× 或 2× 速度、解说开关、重新开始 |
| 画质 | 自动、经典、标准或精细，会记住你的选择。“自动”默认从标准开始：连续 3 秒里有 10% 的帧超过 20 毫秒就降一档；连续 10 秒帧时间都低于 11 毫秒才升一档，每分钟最多升一次（手机自动最高到标准）。手动选了档位就不再自动变化 |
| 声音 | 开启/关闭声音（默认静音）和音量滑块；画面右上角的喇叭按钮也可以开关 |
| 看台氛围 | 看台环境声的音量，0 为关闭，默认 35（中低档）；100 大约等于旧版常驻底噪的响度 |

测试用的网址参数（画面）：`batch=0`（不合批）、`sfreeze=0`（阴影每帧全部重画）、`crease=0`（不画折线高光）、`creasechars=1`（人物也画折线高光）、`subpx=0`（关掉亚像素平滑）、`snap=0`（关掉像素吸附，只用来演示平移闪烁）。

测试用的网址参数：`?speed=20`（模拟加速）、`len=4|8|12|20`、`surface=asphalt`、`tod=night`、`cam=tv`、`home=0&away=3`、`q=auto|low|mid|high`（画质，优先于记住的选择）。

## 声音

默认静音。点击“开启声音”（或画面右上角的喇叭）后才会启动音频（浏览器要求用户先点一下），旁边的滑块调音量。暂停比赛时声音一起暂停，切到别的标签页时也会暂停。

- **声音导演：** 比赛引擎在发生事件的那一刻把事件交给声音导演：开球、传球和射门（按力度区分）、停球、弹地、地面滚动、抢断、犯规、扑救（接住 / 托出 / 封堵）、击中门柱或横梁、射偏、进球、球撞网和围网、滑跪庆祝、中场两声哨、终场三声哨。同一帧里产生的所有事件都在 Web Audio 时钟的同一个时间点排程，所以声音和画面落在同一帧；倍速（1×/2×）和暂停都会被尊重。
- **球声按场地区分：** 橡胶（闷）、沥青（脆亮）、人造草（软、带草声）、木地板（空心的木头声，混响更多），弹地和滚动声也随场地变化。
- **看台氛围（2026-11-03 改版）：** 不再循环播放一条底噪。平时几乎只剩极轻的远处环境声（由 66 秒互不相同的远处人声素材实时随机拼接、交叉淡化，不会形成固定循环），每隔几秒到十几秒（随机间隔）会从某一块看台冒出一句零星交谈、一声咳嗽、一阵笑声或一个人喊“加油”，每一段都随机变调、变长短、换滤波。比赛逼近球门时环境声自然升起，平淡时回落。默认响度比旧版低约 9 dB，可以在战术板的“看台氛围”滑块调节或关闭。
- **分层人群：** 远处环境 + 紧张层（球离球门越近越紧张，平滑升降）+ 惊叹 / 叹息（射偏、扑救、中柱）+ 进球欢呼（主队进球更响，客队进球时主队看台会叹气）+ 掌声和口哨。每块看台是一路独立的声音，按看台在画面里的位置做立体声，随镜头旋转而移动；被切掉的近侧看台会变小声。新反应会交叉淡入并压下旧反应，裁判吹哨时人声自动降低一点。每次播放都会随机挑版本、微调音高和起始点，避免听出重复。
- **合成与录音（按盲听结果定稿）：** 每一层声音单独选择来源。裁判哨声（犯规短哨、开球长哨、中场两声、终场三声）、射偏后的叹息、进球欢呼用少量 CC0 录音（`crowd-cc0.mp3`，约 0.4 MB）；看台常驻低语、紧张层、惊叹、掌声、所有球声和看台上个人喊“加油”都在浏览器里用 Web Audio 程序合成（合成在 Web Worker 里完成，不卡画面）。如果录音文件加载失败，这几层会自动退回合成声。
- **试听页：** [`sound-test.html`](sound-test.html) 可以逐类盲听每种声音的 2–3 个版本（A/B/C）。盲听已经完成，游戏按结果定稿；因为精简后的录音文件不再包含底噪、惊叹和掌声录音，试听页里这几类的“录音”版本现在会退回合成声。

测试用的网址参数：`amb=0..1`（看台氛围音量，0 为关闭）、`crowd=rec|hybrid|synth`（不用定稿配置，改成旧的整体模式：人群全录音 / 底噪合成+反应录音 / 全部合成；注意录音文件现在只含哨声、叹息和欢呼，缺的层会退回合成）、`whistle=synth|rec`、`seed=N`（固定随机种子）。

## 字体

三维场景里的文字使用 **缝合像素字体 / Fusion Pixel Font**（版本 2026.10.25，zh_hans 比例宽度，8px / 10px / 12px），作者 TakWolf，https://github.com/TakWolf/fusion-pixel-font 。该字体以 [SIL Open Font License 1.1](https://openfontlicense.org)（OFL-1.1）发布，许可全文见 [OFL.txt](https://github.com/TakWolf/fusion-pixel-font/blob/master/LICENSE-OFL)。

`index.html` 里只嵌入了场景用到的几十个字形的位图（由构建脚本从官方 BDF 文件转换，未改动字形），不是完整字体文件，也不以“Fusion Pixel”名义另行分发字体。Copyright (c) 2022, TakWolf (https://takwolf.com)。缝合像素字体本身整合了方舟像素字体、Cubic 11、Galmuri、美咲フォント等上游像素字体，它们的许可见字体仓库发布包里的 `LICENSES/` 目录。

## three.js 代码

`index.html` 里有两处改编自 three.js r160 官方示例代码（[MIT 许可](https://github.com/mrdoob/three.js/blob/r160/LICENSE)，Copyright © 2010-2023 three.js authors）：合批用的 `mergeGeometries` / `mergeAttributes`（来自 `examples/jsm/utils/BufferGeometryUtils.js`，删去了变形目标和分组），以及后处理里的法线折线判断（来自 Kody King 编写的 `examples/jsm/postprocessing/RenderPixelatedPass.js`，改成在我们自己的低分辨率 + 调色板通道里运行）。亚像素平滑相机是按 t3ssel8r 公开讲过的思路、参考 David Holland《3D Pixel Art Rendering》一文自行实现的，没有使用他们的代码。
